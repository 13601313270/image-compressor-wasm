# image_compressor — WASM Image Compression Tool

## Introduction

A pure front-end image compression tool that reduces image file size by adjusting **quality** and **target format (jpeg/png)**. Compression runs entirely in the browser — original images are never uploaded and no server resources are used.

- Built with Rust + `wasm-bindgen`; codecs are based on the Rust [`image` 0.24.9](https://crates.io/crates/image) crate
- Decoding (input) supports: PNG, JPEG, WebP, GIF, BMP, TIFF, ICO and other common formats
- Encoding (output) supports: **JPEG and PNG only**
- Compression is synchronous CPU work and blocks the calling thread

## Files

| File | Purpose |
| --- | --- |
| `image_compressor.js` | JS glue code generated by wasm-bindgen: loads the wasm and handles memory copies between JS and wasm |
| `image_compressor_bg.wasm` | The actual compression logic binary; must live in the same directory as the `.js` file |

> The glue code loads the binary via `new URL('image_compressor_bg.wasm', import.meta.url)` by default. This project uses Vue CLI 5 (webpack 5), which recognizes that syntax and emits the wasm as a static asset — **do not rewrite the load path manually**, and do not copy only one of the two files.

## API

### `default export: init(module_or_path?)`

Initializes (loads and instantiates) the wasm and returns a Promise. **You must `await` it before calling the compression function.**

- No argument: automatically fetches `image_compressor_bg.wasm` from the same directory (recommended)
- Pass an `ArrayBuffer`/`Buffer`: skips the fetch and instantiates directly (for Node environments)
- Initialization only needs to run once; repeated calls return the already-instantiated module

### `initSync(module)`

Synchronous version of the initialization. You must supply the wasm binary yourself (a `WebAssembly.Module` or an ArrayBuffer).

### `compress_image(input, quality, format): Uint8Array`

Performs the compression.

| Parameter | Type | Description |
| --- | --- | --- |
| `input` | `Uint8Array` | Binary content of the original image file (from `file.arrayBuffer()`) |
| `quality` | `number` | Quality, **an integer in the valid range 1–100**; lower values mean smaller size and lower visual quality |
| `format` | `string` | Output format; accepts `'jpeg'` or `'png'` only |
| Return value | `Uint8Array` | The compressed image binary; on failure it returns an **empty array (length = 0) and does not throw** |

## Usage Example

```ts
// 1. Load on demand (keeps the wasm out of the main bundle)
const { default: init, compress_image } = await import('image-compressor-wasm')

// 2. Initialize (once only; cache it in a window variable or a module singleton)
await init()

// 3. File -> Uint8Array
const arrayBuffer = await file.arrayBuffer()
const uint8Array = new Uint8Array(arrayBuffer)

// 4. Compress
const compressed: Uint8Array = compress_image(uint8Array, 50, 'jpeg')

// 5. Always check for emptiness: an unsupported output format, a corrupt image,
//    or a decoding failure all return an empty array
if (!compressed.length) {
  throw new Error('Image compression failed')
}

// 6. Uint8Array -> Blob/File, for preview or upload
const blob = new Blob([compressed], { type: 'image/jpeg' })
const url = URL.createObjectURL(blob)              // preview
const newFile = new File([blob], file.name, { type: 'image/jpeg' }) // upload
```

## Parameter Edge-Case Behavior (measured)

All of the following are measured results. Production code should not rely on these implicit behaviors — validate your inputs yourself:

- `quality` is treated as a `u8`: values `> 100` are clamped to 100, while negative numbers and `256` etc. produce unexpected values due to byte truncation (e.g. `-10` behaves like 100, `256` behaves like 0). **Apply `Math.min(100, Math.max(1, Math.round(quality)))` before calling.**
- Passing an unsupported output format such as `'webp'` or `'gif'` returns an empty `Uint8Array` without throwing.
- Passing input that is not a valid image (or contains undecodable content) returns an empty `Uint8Array` without throwing.
- Therefore **you must check the returned length after every call**.

## Notes

1. **Initialize first**: calling `compress_image` before `await init()` has completed will throw.
2. **Failures do not throw**: failure is always signaled by an empty array, so callers must check for emptiness explicitly and notify the user.
3. **JPEG has no alpha channel**: converting a PNG with a transparent background to JPEG loses the transparency (the transparent area renders with the image's own RGB values, usually black/noise). Use PNG output when you need transparency.
4. **Synchronous and blocking**: compressing large images may cause UI jank. For very large images, consider calling it inside a Web Worker.
5. **Compression does not resize**: this tool only adjusts encoding quality; the output keeps the original width and height and is not scaled.
